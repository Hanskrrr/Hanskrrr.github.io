游戏里一个不起眼的房间，可能藏着作者的名字；浏览器的错误页面，可能装着一整个小游戏；平时只负责安装软件的命令行工具，也可能突然画出一头牛。

这些额外的小安排，通常被称为彩蛋，英文是 Easter egg。它们不承担软件最主要的任务，却能让使用过程多出一点意外。有些是程序员的玩笑，有些是向旧作品致意，还有一些留下了创作者自己的故事。

彩蛋有趣的地方，在于它很难用功能清单来概括。下面这几种常见的形式，就各有各的来历。

藏在游戏里的署名

Atari 2600 的《Adventure》里有一个隐藏房间，显示着“Created by Warren Robinett”。这句话的意思很简单：由 Warren Robinett 创作。

把名字藏进游戏，是因为 Atari 当时不为游戏程序员公开署名。Robinett 希望自己的劳动能留下痕迹，便在游戏世界里安排了这样一个地方。Atari 后来的官方回顾讲述了这段往事；Robinett 自己也把它比作画家在画作角落签名。Atari 的回顾、Robinett 本人访谈

这个房间没有给玩家更强的武器，也没有替他们完成冒险。它只是让一个原本被产品名称遮住的人，短暂地站到了作品前面。玩家看到的不再只有角色、场景和规则，还会意识到：这些东西是某个人做出来的。

《Adventure》经常被称作“第一个游戏彩蛋”，但这个说法不够严谨。研究者 Ed Fries 曾与开发者一起调查 1977 年的街机《Starship 1》，并在代码和实机中确认了更早的隐藏问候。对于《Adventure》，称它为最著名的早期彩蛋之一更合适。Ed Fries 的调查记录

后来，彩蛋的内容逐渐丰富起来。它可以是署名，也可以是对前作的引用、团队内部的笑话，或 Konami Code 这样的老游戏典故。同一个细节，有人只觉得有趣，有人则能认出它与另一部作品的联系。

断网页面里的小恐龙

Chrome 的小恐龙是另一种很典型的彩蛋：它藏在一个多数人本来不愿意看到的页面里。

网络中断时，浏览器无法继续加载内容。错误提示可以解释发生了什么，却解决不了等待时的无聊。Chrome 的开发团队于是让页面上的像素恐龙跑了起来，变成一个躲避障碍、不断挑战分数的小游戏。

Google 对创作团队的访谈记载，这个游戏于 2014 年加入。选择恐龙还有一层玩笑：没有网络，仿佛回到了没有 Wi-Fi 的“史前时代”。沙漠、仙人掌和简单的像素画面，让这个设定几乎不用解释就能成立。Google 对创作团队的访谈

小恐龙并没有让网络恢复，但它改变了错误页面的气氛。原本只能等待的地方，多了一件可以做的事。它的规则也足够简单，不需要先学习复杂的操作，几次尝试就能知道怎样玩。

官方后来还提供了 chrome://dino 这个内部页面，让人即使没有断网也能打开游戏。这也说明，彩蛋不一定要永远鲜为人知。一个隐藏功能被大家发现后，只要本身足够好玩，仍然可以拥有很长的生命。

软件包管理器里的牛

APT 是 Debian 等系统使用的软件包管理工具。它日常处理的是下载、安装、更新和依赖关系，看起来与动物没有什么关系，却藏着一个叫 moo 的小功能。

在装有相应工具的环境里，apt-get moo 会显示字符组成的牛，并附上一句问候。常见的一句是“Have you mooed today?”，可以译成“你今天哞过了吗？”

这幅画不是图片文件：括号可以充当眼睛和脑袋，斜线可以拼出身体和腿，字符按照固定的行列排开，就有了轮廓。这样的字符画很适合终端，只有文字也能表达形象。

在 Debian 保存的 APT 源码镜像里，可以看到这个功能的命令分派和绘制代码，其中还包含不同的牛与日期相关变体。具体看到哪幅图，可能随版本和日期而变化。APT 命令分派、字符牛的绘制代码

这个彩蛋的技术并不复杂，趣味主要来自反差。工具刚才还在一本正经地报告软件包信息，接下来却用同样严肃的终端窗口，向你展示了一头牛。它没有实用价值，但很容易让人记住。

打错字时驶过的火车

Unix 风格的命令行中，ls 通常用来列出文件。两个字母顺序写反，就会变成 sl。程序员 Toyoda Masashi 围绕这个容易发生的错误，做了一个小程序。

运行 sl 时，一列由字符绘制的蒸汽火车会从终端驶过。SL 指 Steam Locomotive，作者把它介绍为针对误输入的玩笑命令。sl 作者仓库

严格地说，它是一个独立程序，并不是 ls 自己藏起来的功能。电脑上需要先装有这个程序，打错字时才可能遇见火车；否则通常只会得到“命令未找到”的提示。

不过，它与彩蛋有很相近的趣味。用户本来只是在完成一件普通工作，甚至只是犯了一个小错，却意外得到一段作者精心准备的回应。火车经过之后，任务还是原来的任务，但这次打字错误往往比许多正确操作更让人印象深刻。

小恐龙利用了等待的空隙，火车利用了拼写错误。它们都把软件使用过程中一个容易被忽略的时刻，变成了可以讲给别人听的小故事。

有些彩蛋，乐趣在于认出出处

隐藏署名、小游戏和字符画都很直观，还有一类彩蛋则依赖读者或玩家已有的经验：一个熟悉的名字、一件背景道具、一句似曾相识的台词。

这类引用未必带来额外奖励，也不一定需要做什么才能看见。不了解出处的人可以照常阅读或游玩，熟悉出处的人则会多理解一层。彩蛋因而像一种作品之间的对话，创作者用很小的篇幅，表达自己的喜好和受过的影响。

这里也有一个容易混淆的地方：并不是所有相似之处都是彩蛋。有时是共同的题材，有时是设计习惯，也可能只是巧合。判断一个细节是否有意致敬，创作者的说明和制作资料，比单凭外观联想更可靠。

为什么这些小安排值得记住

把这些例子放在一起，会发现“彩蛋”其实涵盖了很不相同的东西。

形式 例子 额外带来的体验
隐藏署名 《Adventure》的作者房间 看见作品背后的创作者
小游戏 Chrome 的断网恐龙 给等待增加一点乐趣
工具里的玩笑 APT 的字符牛 在严肃任务中遇到反差
独立玩笑程序 终端里的 sl 火车 让一次失误变得有趣
致敬与引用 对旧作品的角色、台词或设定的引用 认出作品之间的联系

它们通常都不是软件非有不可的部分。没有字符牛，软件包管理器依然能完成工作；没有隐藏署名，游戏依然可以通关。可这些看似多余的安排，会让人记住某个具体的瞬间。

一枚让人喜欢的彩蛋，也需要把握分寸。它可以出乎意料，却不该让正常任务无法继续；可以有自己的个性，也不必抢走整个作品的注意力。很多时候，短短一句话、一幅小画或一段轻巧的动画，就已经足够。

软件有时显得很抽象：功能、规则、界面，一层层排列得十分整齐。彩蛋让这些整齐的东西偶尔露出一点人的兴趣和幽默。这也是为什么，一个几十年前留下的名字，或一头没有任何实用功能的牛，至今仍值得被谈起。
